# 拒答守卫标定

对象：`lib/refusal-guard.js` 的 `looksLikeRefusal()`（L4 的判定器）。
复现：`node scripts/calibrate-refusal.mjs --real`

## 判定规则

不是命中即拒，而是打分：

| 信号 | 分值 | 例 |
| --- | --- | --- |
| 开场（段首抱歉 / 身份声明 / Unfortunately） | +3 | `很抱歉…`、`As an AI…`、`Unfortunately…` |
| 强词（无法协助 / 违反政策 / 出于安全考虑 / can't proceed …） | +1 每条 | `这违反了我的使用政策`、`for safety reasons` |
| 交付物特征（代码块、行内代码、`here is the patch`、`下面是`） | −2 | 正文里恰好出现 `cannot` 时救命 |

`score >= 2` 判为拒答；超过 1500 字符的正文直接按交付物处理（拒答不会写这么长）。

## 结果（2026-10-22，本机）

| 集 | 规模 | 结果 |
| --- | --- | --- |
| 合成拒答集 | 40 条（中英，含软拒答、政策拒答、能力声明） | 命中 40，**recall 100%** |
| 合成正常集 | 20 条（含「正文引用 sorry / 违反 / 不能」的假阳性陷阱） | 误判 0，**precision 100%** |
| 本机真实语料 | 56 个会话、**6907 条 assistant 消息** | 判为拒答 **0 条（0.00%）** |

真实语料从 `$DSH_HOME/sessions/**/session.*.jsonl.zstd` 解出（多帧拼接，按 zstd magic 切帧），只取 `assistant/message`。

## 怎么读这组数字

- **误判 0.00% 是有分量的**：6907 条真实输出里一条都没被误伤，说明「交付物减分」和「强词要两条」这两道闸有效。
- **recall 100% 要打折**：合成集是我按已知拒答句式手写的，属于「同分布自测」，不能代表所有模型。真实拒答样本几乎为 0（本机历史基本是被破甲后的输出），所以**真实召回率没有被测到**。
- 结论只到这一步：**低误判已验证，召回待真实拒答样本验证**（ROADMAP P1-7 的剩余部分）。

## 调优记录

| 版本 | 改动 | recall | FP |
| --- | --- | --- | --- |
| 1.2.1 | 布尔判定（开场即拒 + 两条强词） | 72.5% | 5%（1/20） |
| 1.2.2 | 改打分制；补 `unfortunately` / `I'm unable` / `违反…政策` / `绕过…限制` / `请换个方向`；交付物 −2 | 100% | 0% |

## 已知盲区

1. **间接拒答**：不写「抱歉」，改用「我们先从合规角度分析」这类绕行，检测器抓不到。
2. **多语言**：目前只有中英；日韩德法未覆盖。
3. **分片输出**：只检查完整 assistant 消息；流式中断时可能拿不到全文。
4. **工具拒绝**：不在本检测器范围内（`tool/result` 里的拒绝还没接进 L4，见 ROADMAP P1-8）。
